# Нагрузочные тесты (k6)

Сценарии бьют в общий стенд `http://195.63.138.24:4000` (см. `lib.js`).
В CI они **не запускаются автоматически** — джоба `k6`
стартует только вручную через «Run workflow». Ниже — как гонять
те же сценарии локально.

## Сценарии

| Файл       | Что делает                                          | Нагрузка              |
|------------|-----------------------------------------------------|-----------------------|
| `smoke.js` | Дымовой: health → каталог → товар → корзина, 5 VU   | 30 сек                |
| `load.js`  | Нагрузочный: цикл «каталог → в корзину → заказ»     | рампа до 20 VU, ~1 мин |
| `spike.js` | Спайк: фон 5 → всплеск 50 → пик 100 → спад, чтение | стадии, ~1.5 мин      |
| `todos.js` | CRUD todo: список → фильтры → создать → обновить → удалить | рампа до 10 VU, ~1.5 мин |
| `mixed.js` | Смешанный: shop-поток + todo-поток одновременно     | пик 20 VU             |

`todos.js` удаляет созданное за собой — базу перед прогоном сбрасывать не нужно.
Корзина — синглтон на всех VU: чужой `checkout` честно отвечает
400 «Cart is empty», это норма, а не падение (см. комментарий в `load.js`).

## Запуск локально

Нужен установленный k6: https://grafana.com/docs/k6/set-up/install-k6/

```bash
cd tests/k6

# дымовой прогон (быстрая проверка, что стенд жив)
k6 run smoke.js

# любой другой сценарий
k6 run load.js
k6 run spike.js
```

Прогон красный, если превышены пороги (`thresholds` в начале каждого файла),
например `http_req_failed: rate<0.01` или `p(95)<3000` по длительности.
В конце k6 печатает сводку — по ней видно, какой порог не сошёлся.

## Запуск из CI (вручную)

1. Открыть репозиторий на GitHub → вкладка **Actions** → workflow **CI**.
2. Нажать **Run workflow**, в поле **k6-script** выбрать сценарий:
   `smoke.js` (по умолчанию), `load.js` или `spike.js`.
3. Нажать **Run workflow** — запустится только джоба `k6`,
   остальные джобы при ручном запуске пропускаются.
